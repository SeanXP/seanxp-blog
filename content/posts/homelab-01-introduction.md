在云服务盛行的今天，为什么还要搭建 HomeLab？本文将分享我对 HomeLab 的理解、架构设计理念，以及硬件选型的思考过程，帮助你找到适合自己的方案。
<!--more-->

## 为什么要搭建 HomeLab？

在这个数据即资产的时代，**通过 HomeLab 自建一些服务（如 Tiny Tiny RSS、BitWarden、Jellyfin），将云服务私有化，让个人隐私留在自己的硬盘之中**，可能是最好的解决方案。

HomeLab（家庭实验室）不仅仅是一台服务器，更是一种理念：

1. **数据主权**：你的数据，你做主
2. **隐私保护**：敏感数据不出家门
3. **学习平台**：实践虚拟化、容器化、网络配置等技能
4. **成本优化**：长期运行可能比订阅云服务更经济
5. **折腾乐趣**：享受 DIY 的成就感（可太快乐了）

当然，也要考虑：
- **电费成本**：7x24 小时运行的电费
- **维护成本**：需要技术能力和时间投入
- **硬件投资**：初期投入

## HomeLab 的两种架构理念

HomeLab 有两种截然不同的玩法：

### AIO（All-in-One）：集中式架构

一台强大的服务器，通过虚拟化跑各种服务，扩展各种硬件接口，满足所有需求。

**优点：**
- 集中管理，易于维护
- 资源利用率高
- 性能强劲，可应对各种场景

**缺点：**
- 单点故障风险高
- 初期投资大
- 功耗较高
- 扩展受限于单台设备

### One by One：分布式架构

通过多台小型、低功耗、廉价的专用硬件，专器专用，互相协同，可迁移可替换。

**优点：**
- **避免单点故障**：某个服务挂了不影响其他
- **可玩性高**：可以尝试更多硬件
- **灵活迁移**：服务可以轻松在设备间迁移
- **渐进式投资**：按需添加设备
- **功耗可控**：只运行必要的设备

**缺点：**
- 管理相对分散
- 设备数量多，占用空间
- 需要更好的组织能力

### 我的选择：One by One + KISS 原则

我倾向 **One by One** 架构，原因如下：

1. **容错性**：路由器挂了不影响 NAS，NAS 挂了不影响媒体服务器
2. **可维护性**：故障排查更简单，升级替换更灵活
3. **可玩性**：可以体验不同硬件平台和架构
4. **渐进式**：可以根据需求逐步添加设备

同时遵循 **KISS（Keep It Simple, Stupid）原则**：

- **所有服务用 Docker 部署**
- **启动脚本和配置文件统一放在 Git 仓库管理**
- **可以低成本将服务在不同主机间迁移**
- **避免过度复杂的配置**

这样的架构设计让我可以：
```bash
# 在任何主机上快速部署服务
git clone my-homelab-configs
cd my-homelab-configs/jellyfin
docker-compose up -d
```

## 硬件选型考量

在选择硬件之前，先明确几个问题：

### 1. 主要用途

- 虚拟化平台（PVE/ESXi）
- 软路由（OpenWrt）
- 媒体服务器（Jellyfin/Plex）
- 智能家居中枢（Home Assistant）
- 私有云服务（Bitwarden、RSS、网盘）
- 开发测试环境

### 2. 性能需求

- **CPU**：核心数、频率、是否需要硬件解码
- **内存**：容量需求（虚拟机吃内存）
- **存储**：速度和容量的平衡
- **网络**：千兆还是万兆

### 3. 功耗与成本

以 30W 功耗为例：
- 年耗电：30W × 24h × 365d = 262.8 kWh
- 年电费：262.8 × 0.6元 = 157.8元

功耗每增加 10W，年电费增加约 52元。

## 平台对比：x86 vs ARM

### x86 平台（Intel/AMD）

**优点：**
- **生态成熟**：软件兼容性极好
- **虚拟化支持完善**：PVE、ESXi、Hyper-V
- **可玩性高**：各种硬件直通、虚拟化方案
- **性能强劲**：适合重度虚拟化
- **硬件解码**：Intel Quick Sync、AMD VCN

**缺点：**
- 功耗相对较高
- 发热量大

### ARM 平台（Apple Silicon/树莓派）

以 Mac Mini M4 为例：

**优点：**
- 工艺优秀：3nm 制程，低功耗、散热好、无噪音
- 性能强劲：单核、多核、GPU 性能都很好
- macOS 生态：与 iPhone/iPad/MacBook 无缝连接
- 远程管理：内置屏幕共享

**缺点：**
- **x86 的可玩性远超 ARM**：这不是一个量级的差别
- **ARM 生态不成熟**：很多 Docker 镜像不支持 ARM
- **macOS 不适合做服务器**：很多操作需要 VNC，SSH 无法完全搞定
- **性价比低**：几百元的 x86 主机可玩性都远超它
- 扩展性差

**结论**：不建议专门购买 Mac Mini 做 HomeLab 主机。除非你本身就有，否则 x86 平台是更好的选择。

## 我的硬件清单

基于 One by One 理念和实际需求，我的 HomeLab 由以下设备组成：

### 核心计算：天钡 GEM12 Max

这是整个 HomeLab 的核心主机，运行 Proxmox VE（PVE）虚拟化平台。

**配置：**
- CPU: AMD Ryzen 9 6900HX（8核16线程）
- 核显: Radeon 680M（支持硬件解码）
- 内存: 英睿达 16GB DDR5 4800 × 2（共 32GB）
- 存储: 希捷酷玩520 1TB NVMe SSD
- 网卡: Intel i226V 2.5G

**价格：**
- 准系统: 1610元（拼多多百亿补贴）
- 内存 32GB: 456元
- SSD 1TB: 359元
- **总计: 2425元**

**为什么选择它：**
- **性能充足**：8核16线程足以运行多个虚拟机
- **硬件解码**：Radeon 680M 支持视频转码
- **功耗合理**：TDP 45W，实际使用 20-40W
- **网络性能**：2.5G 网口满足家庭需求
- **价格合理**：2400元的价格，性能超越很多 5000元 的方案

### 网络设备

**路由器：**
- 主路由: TP-LINK 7DR7290
- AP: TP-LINK XDR5480
- 通过无线 Mesh 组网，覆盖全屋 WiFi

**交换机：**
- TP-LINK 8口千兆交换机

**用途：**
- WiFi 接入（作为 AP 使用）
- 主路由在 PVE 中运行 OpenWrt 虚拟机
- 交换机连接各个有线设备

### 存储设备

**NAS：群晖 DS216+II**
- 2盘位 NAS
- 主要用于文件存储和备份
- 暂无升级计划

### 智能家居

**网关：**
- 小米中枢网关
- 小米智能多模网关2

**用途：**
- 连接 Zigbee/蓝牙设备
- 配合 Home Assistant 实现自动化

## 部署架构

```
Internet
    │
    ├─ 光猫（桥接模式）
    │
    ├─ GEM12 Max (PVE)
    │   ├─ OpenWrt VM（主路由）
    │   ├─ Ubuntu VM（Jellyfin + 核显直通）
    │   └─ Home Assistant VM
    │
    ├─ TP-LINK 路由器（AP 模式，Mesh 组网）
    │
    ├─ 群晖 NAS（文件存储）
    │
    └─ 小米网关（智能家居）
```

所有应用服务均通过 Docker 部署，配置文件存储在 Git 仓库，实现：
- 版本控制
- 快速迁移
- 灾难恢复

## 总结

HomeLab 的核心不在于硬件有多贵，而在于：

1. **明确理念**：AIO 还是 One by One，根据需求选择
2. **合理选型**：性能、功耗、价格的平衡
3. **优雅架构**：Docker + Git，简单可维护
4. **渐进式构建**：从核心功能开始，逐步完善

**我的建议：**
- 预算 2000-3000元：选择类似 GEM12 Max 的 AMD 迷你主机
- 预算 1000-2000元：选择 N100 平台（适合轻量需求）
- 预算充足：可以考虑服务器平台或高端 DIY

**避免的坑：**
- ❌ 不要买 ARM 平台做主力（Mac Mini、树莓派）
- ❌ 不要过度追求性能（够用就好）
- ❌ 不要忽视功耗（长期成本）
- ❌ 不要过度复杂的架构（KISS 原则）
